# 麦门签 · 今天吃什么？

**三根薯条，一卦定一餐。**

先选早餐、午餐或晚餐，点一下薯条盒，随机得到一份主食、配餐和缺货替换食帖。八卦用于视觉玩法，结果只描述口味，不预测运势。

> 在线体验：<https://dovesoup.github.io/maimen-qiantong/>
> 本地打开：`python3 -m http.server 8899 -d web`，访问 `http://localhost:8899/`

---

## 目标用户

- 工作日午休只有几十分钟、不想再刷菜单的上班族；
- 到了麦当劳门口还在问“吃哪个”的学生与朋友小团体；
- 希望打开就能得到一个点餐答案的人；
- 早餐和午晚餐都想快速决定，且不喜欢负面抽签结果的人。

---

## 为什么做这个

「今天吃什么」不是没有答案，而是答案太多。打开外卖菜单，人又被推回选择。

麦门签只做一件事：**用一次有仪式感的随机，替你把选择收窄到一个可以执行的结果。**

结果标签是顶饱、清爽、热烈、酥脆、入味、浓郁、慢吃、当令，描述食帖的口味风格。

## 玩法

1. **先选餐段**：首页只显示早餐、午餐、晚餐三个图标按钮。午餐和晚餐共用正餐菜单，页眉保留所选餐段。
2. **摇三根薯条**：点击薯条盒、按「摇一签」，或在桌面端快速左右移动鼠标。
3. **落成一卦**：阳爻是一根完整薯条，阴爻是两根短薯条留缝。三爻共八种结果。
4. **照单点餐**：一次只显示一个主食、两样配餐和一份完整替换。菜单共 18 份食帖：8 份早餐、10 份午晚正餐。

## 设计边界

### 不和城市绑定

不查询用户城市或门店。用八个相对稳定的全国核心锚点（巨无霸、麦辣鸡腿堡、板烧鸡腿堡、麦香鸡、麦香鱼、双层吉士汉堡、麦乐鸡、那么大鸡排）作为结果骨架。

数据来自 11 城麦当劳 MCP 菜单快照：基础正餐锚点在 11 家有效门店中全部出现；基础早餐锚点在 9 家有效早市门店中全部出现。新增两款安格斯只在部分样本门店出现，结果明确提示部分门店供应，并给出基础菜单的替换食帖。抽样不能保证当前全国供应。

### 不展示价格

不抓取、不展示单价或合计价，也不按价格决定签等。价格随城市、门店和活动变化，绑定价格会让页面很快过期，也会把「吃什么」变成「花多少钱」。

### 用口味标签描述结果

保留八种卦象作为薯条排列的视觉形式，取消“大吉／中吉／小吉／平”等运势档位。页面只给随机点餐结果与口味标签。

### 新品只做条件签

不追踪实时新品。坤卦保留「当令尝新」的意思：

> 若有当季鸡肉新品，请店员替你选一个；没有，就落到固定的鸡肉食帖。

这是一条永远成立的条件句，不需要维护新品数据库。

## 麦当劳 MCP 怎么用

MCP 是**构建时数据来源**，不是网页运行时接口：

- 使用 `query-nearby-stores` 找门店，`query-meals` 分别取早市和正餐菜单；
- 从真实返回的品名中核对八个锚点及替换项，不编造菜名；
- 将最终食帖打包进静态页面，网页打开时不携带、不请求 MCP Token。

这样公开部署时不会泄露 Token，也不需要后端。代价是菜单不会自动更新；换季或调价后需要重新采集、核对并构建。

详见 [`MCP_INTEGRATION.md`](MCP_INTEGRATION.md)。

## 本地运行与构建

```bash
# 直接看成品（无需 Token）
python3 -m http.server 8899 -d web

# 修改 gua-matrix.json 后先校验，再重新生成
python3 src/validate_content.py
python3 src/build_site.py

# 重新生成双餐段对照表
python3 src/render_gua_matrix.py
```

如需重新采集菜单（可选）：

```bash
export MCD_MCP_TOKEN=你的token
python3 src/collect_menus.py
```

只读调用，不下单、不支付、不领券、不抽奖。无前端第三方依赖。
